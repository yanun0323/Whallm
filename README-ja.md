Whallm は、Apple Silicon Mac で大規模言語モデルを動かすアプリです。こうしたモデルは「エキスパート」と呼ばれる小さな部品が集まってできていて、1 語ごとに使うのはそのうちの数個だけです。Whallm はどの語でも使う部分をメモリに置き、エキスパートは必要なときだけ SSD から読み込みます。そのため、Mac のメモリよりずっと大きなモデルも動かせます。チャット画面と、OpenAI 互換の API が付いています。

対応モデル：DeepSeek V4、DeepSeek V4.1、Qwen3.8、Swift1.5 Qwen3.8、MiMo（プレビュー）。

## ベンチマーク概要

ユーザーが v1.1.13 で **Swift1.5-Qwen3.8-Flash-Next** を測定しました。入力は 16K トークン、回答は 512 トークンです。**Prefill** は Whallm が入力を読む速さ、**Decode** は回答を書く速さで、どちらも 1 秒あたりのトークン数です。

| チップ | キャッシュモード | Slots | Prefill (tok/s) | Decode (tok/s) | ピークメモリ (GiB) |
| --- | --- | --- | --- | --- | --- |
| M2 Max | 自動 | 8192 | 286.4 | 19.4 | 31.71 |
| M2 Max | 固定 | 2089 | 289.6 | 16.5 | 16.99 |
| M5 Pro | 自動 | 8192 | 521.1 | 25.6 | 31.11 |
| M5 Pro | 固定 | 2089 | 536.0 | 21.7 | 16.25 |

自動モードでは Whallm がキャッシュサイズを決めます。固定モードは小さめの決まったサイズを使うので、メモリは少なくて済みますが、回答を書くのは遅くなります。

> 詳しくは[ベンチマークの全結果](#ベンチマーク)を参照してください。

## はじめに

1. [GitHub Releases](https://github.com/yanun0323/Whallm/releases) から `Whallm-macOS-arm64.zip` をダウンロードし、展開して `Whallm.app` を開きます。
2. **Model** を開き、モデルを選んで **Download Model** を選びます。アプリは先に空き容量を確認します。ダウンロードが止まっても、続きから再開できます。
3. **Server** を開き、**Start Server** を選びます。
4. **Chat** を開いてモデルを選ぶか、下の例のように API クライアントを接続します。

サーバーの既定のアドレスは `http://127.0.0.1:11434` です。モデルは初めて使うときに読み込まれます。サーバーが読み込むモデルは一度に 1 つで、リクエストも 1 件ずつ処理します。インストールしたばかりのモデルが Chat の一覧にない場合は、サーバーを再起動してください。

[1.1.13 のリリースノート](Packaging/ReleaseNotes/1.1.13.md)に、変更点、アップグレード手順、既知の制限があります。

## 動作環境

| 項目 | 条件 |
| --- | --- |
| Mac | Apple Silicon、macOS 15 以降 |
| メモリ | 64 GiB を推奨。実際の使用量はモデルと設定によります |
| ストレージ | 高速な内蔵、Thunderbolt、または USB4 SSD |
| 空き容量 | 途中までのダウンロードも含め、各モデルに必要な容量をアプリが表示します |
| ネットワーク | モデルとアプリ更新のダウンロードに必要です |

アプリにモデルの重みは含まれていません。DeepSeek V4.1 だけでも、エキスパートと Engram のファイルに約 **458 GiB** が必要で、ほかの重みも別に必要です。

## Qwen モデル

2 つの Qwen モデルは、MLX ではなく、Whallm が C++ と Metal で書いた独自のエンジン（**Native エンジン**）を使います。ダウンロード済みのファイル、モデル名、API ID、Alias はそのままです。クライアントがまだ古い `-Native` のテスト用 ID を使っている場合は、下の ID に切り替えてください。古い MLX エンジンが保存したプロンプトキャッシュは引き継がれません。

### Swift1.5-Qwen3.8-Flash-Next

1.1.10 で追加されました。

- API model ID：`swift1.5-qwen3.8-flash-next-mxfp4`
- 提供元：`Yanun/Swift1.5-Qwen3.8-Flash-Next-Whallm-MXFP4`、revision `257cb509d72ecc07519be35a8b7558fde3b31b21`
- ダウンロードサイズ：**127,714,522,478 bytes**（約 **118.94 GiB**）。画像用の重み **897,864,704 bytes** を含みます。
- Qwen3.8 FP8 と同じエンジンを使いますが、フォルダー、設定、Alias、プロンプトキャッシュは別です。

### Qwen3.8-Flash-Next

- API model ID：`qwen3.8-flash-next-fp8`
- Swift1.5 と同じエンジンと設定を使い、インストール、Alias、プロンプトキャッシュは別です。

### 設定

- **Advanced Settings** には、生成、エキスパートキャッシュのサイズ、読み込みワーカー、Prompt Cache、ウォームアップ、MTP、8-bit 常駐重みがあります。
- **Size the expert cache automatically** は既定でオンです。オンのとき、Whallm はモデルを読み込んだ時点の空きメモリを最大約 20 GiB まで使い、macOS とほかのアプリのために、少なくとも 7 GiB またはこの Mac のメモリの 15% を残します。オフにすると、決まったサイズを自分で選べます。
- **MTP** は次の数語を先に予想し、それが正しいか確かめます。既定でオンで、多くの場合は回答が速くなりますが、すべてのプロンプトで速くなるわけではありません。MTP をオフにしたときと、文章が少し変わることがあります。
- **Use 8-bit resident weights** は、メモリに置いたままの部分を小さな形式で保存します。メモリが少なくて済み、多くの場合は回答も速くなり、MTP がオンのときに最も効果があります。この設定をオフにしたときと、文章が少し変わることがあります。新しい設定や初期値に戻した設定ではオンです。保存済みの設定は、以前の選択のままです。

### 画像

- 2 つの Qwen モデルは、Chat、`/v1/chat/completions`、`/v1/responses` で静止画の PNG、JPEG、WebP を受け付けます。
- 画像は MTP のオン・オフどちらでも使えます。画像を含むリクエストはプロンプトキャッシュを使いません。
- 1 回のリクエストで使えるのは、画像 8 枚まで、1 ファイル 8 MiB まで、合計 32 MiB までです。各画像は最大 1,048,576 ピクセルに縮小され、すべての画像で合計 2,048 画像トークンまで使えます。
- 新しくインストールすると、画像用の重みも入ります。以前のインストールでは **Model → Verify and Repair** を選んでください。足りないファイルと壊れたファイルだけをダウンロードします。Qwen3.8 FP8 の完全なインストールは **126,189,355,659 bytes**（約 **117.52 GiB**）です。
- Qwen は動画、音声、文書を受け付けません。
- M2 Max では、2 つのモデルとも短いテキスト、Chat、Responses、ストリーミング、画像が正しく動きました。古い MLX エンジンとは文章が変わることがあります。これらの確認は、あらゆる用途での品質や速度を保証するものではありません。

## DeepSeek V4.1

DeepSeek V4.1 も、MLX ではなく独自の Native エンジンで動くようになりました。ダウンロード済みのファイル、モデル名、API ID、Alias はそのままです。古い MLX エンジンが保存したプロンプトキャッシュは引き継がれません。

- **Advanced Settings** には、生成、エキスパートキャッシュのサイズ、読み込みワーカー、Prompt Cache、ウォームアップ、DSpark があります。
- **Size the expert cache automatically** は既定でオンです。オンのとき、Whallm はモデルを読み込んだ時点の空きメモリを最大約 72 GiB まで使い、macOS とほかのアプリのために、少なくとも 7 GiB またはこの Mac のメモリの 15% を残します。決まったサイズを選ぶ場合は、少なくとも 96 個のエキスパートが入る大きさが必要です。
- MLX でしか使えなかった設定はなくなりました。たとえば近似モード、ANE projection、MLX のメモリ目安です。近似モードを求めるリクエストは拒否されます。
- **DSpark** は次の何語かを先に予想し、それが正しいか確かめます。DSpark のエキスパートはメインのエキスパートキャッシュを共有するので、専用のキャッシュサイズはなくなりました。greedy サンプリングでは、DSpark は文章を変えません。コードのように予想しやすい文章で最も効果があり、ほかの文章ではオフのときより少し遅くなることがあります。
- M5 以降のチップでは、長い入力に GPU の Neural Accelerators を使います。M5 での実測はまだです。
- M2 Max（64 GiB）で、先にファイルキャッシュを空にして測定しました。3,000 トークンの Code プロンプトは約 70 tok/s、16,000 トークンは約 140 tok/s で読み込みました。DSpark なしでは、回答を約 3.4 tok/s で書きました。最近の高速化のあと、DSpark の速さはまだ測り直していません。greedy サンプリングでは、出力は古い MLX エンジンと一致しました。品質、16,000 トークンを超える入力、M5 はまだテストしていません。

## 機能

Whallm はどの語でも使う部分をメモリに置き、必要なエキスパートだけを SSD から読み込みます。DeepSeek V4.1 の Engram の行と Qwen の N-gram の行も、必要なときだけ読み込みます。

| モデル | 速くする方法 |
| --- | --- |
| DeepSeek V4 | 入力を 1 層ずつ読む、エキスパートの計算をまとめて行う、小さめ（FP8）のアテンションキャッシュを使う、ANE projection と DSpark を選べる |
| DeepSeek V4.1 | Native エンジン：長い入力では各エキスパートを 1 回だけ読み、GPU の計算中に読み込む。回答を書くときは、メモリにあるエキスパートから先に計算する。DSpark は予想を確かめるときに、残した語を計算し直さない |
| Qwen3.8 | 入力を読むときにエキスパートをまとめて計算する、読み込みが終わったものからすぐ計算する、QSA キャッシュを圧縮する、次の層を先に読む、MTP を使う |

## Codex の接続

Whallm のサーバーを起動してから、次の内容を `~/.codex/config.toml` に追加します。

```toml
model = "deepseek-v4-flash-0731"
model_provider = "deepseek-v4-ssd"
model_reasoning_effort = "high"

[model_providers.deepseek-v4-ssd]
name = "Whallm"
base_url = "http://127.0.0.1:11434/v1"
wire_api = "responses"
requires_openai_auth = false
```

`model` には API model ID か、**Model → Advanced Settings** で設定した Alias を指定します。その後、Codex を再起動してください。

- Chat、Status、Throughput に出る名前は表示名で、API model ID ではありません。リクエストとベンチマークの JSON には、引き続き API model ID を使います。
- この例は既定のアドレスを使い、API key は使いません。Whallm で key を設定した場合は、クライアントにも同じ key を設定してください。

[Codex の設定リファレンス](https://developers.openai.com/codex/config-reference/)も参照してください。

## API とプライバシー

API はテキストのストリーミングとツール呼び出しに対応しています。エンドポイントは次のとおりです。

- `GET /healthz` と `GET /v1/models`
- `POST /v1/responses`
- `POST /v1/chat/completions` と `POST /v1/completions`
- `POST /api/models/load` と `POST /api/models/unload`

**Seed**（v1.1.8 以降）：3 つの生成エンドポイントはすべて、`0` から `4294967295` までの `seed` を任意で受け付けます。省略するか `null` を送ると、毎回新しいランダムな seed を使います。Chat では、Seed は次のメッセージにだけ使われます。同じ seed で同じ結果になるのは、プロンプト、モデル、設定、バージョンがすべて同じときだけです。キャッシュの状態や高速化の設定が違うと、文章が変わることがあります。`temperature=0` では、常に最も確率の高いトークンを選びます。

**ツール**：ツールを実行して結果を返すのはクライアントです。Whallm が MCP ツールを自分で実行することはありません。v1.1.9 以降、すべてのモデルの `/v1/responses` は、`function_call_output.output` として文字列か、`input_text` のリストを受け付けます。各部分は、間に何も入れずに順番どおりつなげます。リクエストの履歴には、同じ `call_id` を持つ `function_call` を含めてください。

**MiMo（プレビュー）** は、Chat、Responses、アプリの添付ファイルで、静止画と短い PCM WAV 音声を受け付けます。

- JSON のリクエスト本文：最大 **1 MiB**。
- `/api/assets` へのアップロード（サインインが必要）：PNG、JPEG、WebP、PCM WAV と、小さな PDF、DOCX、PPTX、XLSX ファイル。1 つあたり最大 **8 MiB**。
- 音声：24 kHz、16-bit PCM WAV、モノラルまたはステレオ。1 つ 30 秒まで、1 回のリクエストで 2 つまで。
- 非対応：音声出力、動画、`logprobs`、`response_format`、`stop`。

[MiMo の仕様と制限](docs/mimo-development.md)も参照してください。

**プライバシー**：モデルはあなたの Mac で動きます。Whallm がネットワークを使うのは、ダウンロード、アップデート、API 接続のときだけです。接続したクライアントが、データを別の場所に送ることはあります。**Debug** は設定とキャッシュの情報を記録しますが、プロンプト全文、ツールの結果、画像、API key は記録しません。ログを `~/.whallm/server.log` に保存することもできます（最大 10 MB。古い内容から削除されます）。ログにはローカルのパスやネットワークアドレスが含まれることがあるので、共有する前に確認してください。

## 検証と制限

- テスト：**Python テスト 786 件が成功、4 件スキップ**、**Swift テスト 209 件が成功、4 件スキップ**。失敗はありません。
- パッケージを作るときに、アプリの署名と同梱ファイルを確認し、ビルドフォルダーにアクセスできない状態でも英語、簡体字中国語、繁体字中国語で起動できることを確かめます。アプリと、展開した ZIP の両方で確認します。正式リリースでは、署名と公証を済ませたダウンロードでもう一度確認します。
- ツール呼び出しのテストは、決まったモデル出力を使います。Pi や Codex の完全なセッションではありません。
- MiMo はプレビューです。あらかじめ用意した固定のモデルを使い、テキスト、画像、短い WAV 音声、一部の文書に対応しています。動画、音声と映像の同期、MCP Agent の画面はまだ完成していません。[開発状況](docs/mimo-development.md)を参照してください。
- 以前の MTP の測定は、今のエンジンより前のものです。MTP がすべてのプロンプトで速くなるわけではありません。
- 一部の高速化は、小さなモデルや単体の部品でしかテストしていません。
- とても長いプロンプトには、より多くのキャッシュメモリが必要です。
