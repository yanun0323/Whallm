Whallm は、Apple Silicon Mac で大規模言語モデルを動かすアプリです。共通の重みはメモリに置き、各トークンに必要なエキスパートだけを SSD から読み込みます。そのため、メモリよりずっと大きいモデルも動かせます。チャット画面と OpenAI 互換 API を備えています。

対応モデル：DeepSeek V4、DeepSeek V4.1、Qwen3.8、Swift1.5 Qwen3.8、MiMo（プレビュー）。

## ベンチマーク概要

ユーザー提供の **Swift1.5-Qwen3.8-Flash-Next** v1.1.13 の測定値です。Native エンジンを使用しています。以下の概要は独立した **16K 入力／512 出力**の表に基づきます。入力長ごとの全結果は後半に掲載しています。両者は異なる記録値であり、平均していません。

| チップ | キャッシュモード | Slots | Prefill (tok/s) | Decode (tok/s) | ピークメモリ (GiB) |
| --- | --- | --- | --- | --- | --- |
| M2 Max | 自動 | 8192 | 286.4 | 19.4 | 31.71 |
| M2 Max | 固定 | 2089 | 289.6 | 16.5 | 16.99 |
| M5 Pro | 自動 | 8192 | 521.1 | 25.6 | 31.11 |
| M5 Pro | 固定 | 2089 | 536.0 | 21.7 | 16.25 |

元資料の簡易概要と 16K の表ではピークメモリの値が異なります。ここでは 16K の表にある、より細かい値を採用しています。以前の Qwen と DeepSeek の結果は、元のバージョンを明記して後半に残しています。

> 詳しくは[ベンチマークの全結果](#ベンチマーク)を参照してください。

## はじめに

1. [GitHub Releases](https://github.com/yanun0323/Whallm/releases) から `Whallm-macOS-arm64.zip` をダウンロードして展開し、`Whallm.app` を開きます。
2. **Model** でモデルを選び、**Download Model** を押します。アプリが先に空き容量を確認します。ダウンロードが止まっても再開できます。
3. **Server** で **Start Server** を押します。
4. **Chat** でモデルを選ぶか、下の例のように API クライアントを接続します。

サーバーのアドレスは `http://127.0.0.1:11434` です。モデルは最初に使うときに読み込まれます。サーバーが読み込むモデルは一度に 1 つで、リクエストも一度に 1 つずつ処理します。インストールしたばかりのモデルが Chat の一覧にない場合は、サーバーを再起動してください。

変更点、アップグレード手順、既知の制限は [1.1.13 リリースノート](Packaging/ReleaseNotes/1.1.13.md)にあります。

## 動作環境

| 項目 | 条件 |
| --- | --- |
| Mac | Apple Silicon、macOS 15 以降 |
| メモリ | 64 GiB を推奨。実際の使用量はモデルと設定によります |
| ストレージ | 高速な内蔵、Thunderbolt、または USB4 SSD |
| 空き容量 | 途中までのダウンロードも含め、各モデルに必要な容量をアプリが表示します |
| ネットワーク | モデルとアプリ更新のダウンロードに必要です |

モデルの重みはアプリに含まれません。DeepSeek V4.1 はエキスパートと Engram のファイルだけで約 **458 GiB** 必要で、ほかの重みも別に必要です。

## Qwen モデル

両方の Qwen モデルは Native エンジン（C++ と Metal、MLX 不使用）で動作します。既存のダウンロード、モデル名、API ID、Alias は変わりません。2 つの `-Native` テスト用項目は削除されました。その ID を使うクライアントは、下記の元の ID に変更してください。MLX 専用設定は適用されず、MLX のプロンプトキャッシュも再利用しません。

### Swift1.5-Qwen3.8-Flash-Next

1.1.10 で追加されました。

- API モデル ID：`swift1.5-qwen3.8-flash-next-mxfp4`
- 取得元：`Yanun/Swift1.5-Qwen3.8-Flash-Next-Whallm-MXFP4`、リビジョン `257cb509d72ecc07519be35a8b7558fde3b31b21`
- ダウンロードサイズ：**127,714,522,478 bytes**（約 **118.94 GiB**）。テキストと MTP の 59 ファイルに、画像用の重み **897,864,704 bytes** を含みます。監査用ファイルはダウンロードしません。
- Qwen3.8 FP8 と同じ推論エンジンを使いますが、フォルダー、設定、Alias、プロンプトキャッシュは別々です。

### Qwen3.8-Flash-Next

- API model ID: `qwen3.8-flash-next-fp8`
- Qwen3.8 FP8 は Swift1.5 と同じ Native エンジンと設定を使います。インストール、Alias、プロンプトキャッシュは別々です。

### 設定

- 両モデルで生成、エキスパートキャッシュサイズ、読み込みワーカー、Prompt Cache、ウォームアップ、MTP、8-bit 常駐重みを設定できます。MLX メモリ指針、先読みワーカー、キャッシュ削除方式、独立した MTP キャッシュサイズは表示しません。
- **詳細設定**の「エキスパートキャッシュのサイズを自動で決める」は初期設定でオンです。オンのとき、エンジンはモデル読み込み時の空きメモリからサイズを決め、上限は約 20 GiB です。macOS とほかのアプリのために、7 GiB またはこの Mac のメモリの 15% の多いほうを残します。オフにすると固定サイズを指定できます。ほかの設定は生成、読み込みワーカー、プロンプトキャッシュ、ウォームアップ、MTP、8-bit 常駐重みです。
- MTP は初期設定でオンです。多くの場合は出力が速くなりますが、すべてのプロンプトで速くなるわけではありません。MTP オフのときと出力が少し変わることがあります。
- **Use 8-bit resident weights** は、新しい設定と初期値に戻した設定ではオンです。保存済みの設定は以前の選択のままです。オンにすると、メモリに常駐する重み（エキスパートを除く）を BF16 ではなく 8-bit で保持します。メモリ使用量が減り、多くの場合は出力も速くなります。効果が最も大きいのは MTP オンのときです。オフのときと出力が少し変わることがあります。

### 画像

- 両方の Qwen モデルで、Chat、`/v1/chat/completions`、`/v1/responses` から静止 PNG、JPEG、WebP 画像を入力できます。
- 画像は MTP のオン・オフどちらでも送れます。画像リクエストではプロンプトキャッシュを使いません。
- 1 リクエストあたりの上限：画像 8 枚、1 ファイル 8 MiB、合計 32 MiB、縮小後 1 枚あたり 1,048,576 ピクセル、画像トークン 2,048。
- 新規インストールには画像用の重みが含まれます。以前のインストールでは **Model → Verify and Repair** を選んでください。足りないファイルと壊れたファイルだけをダウンロードします。Qwen3.8 FP8 の完全なインストールは **126,189,355,659 bytes**（約 **117.52 GiB**）です。
- Qwen では動画、音声、文書の入力は使えません。
- M2 Max では両モデルの Native による短いテキスト、Chat、Responses、ストリーミング、画像を確認しています。ユーザー提供の v1.1.13 Swift1.5 の M2 Max と M5 Pro での速度測定値を以下に掲載しています。出力は MLX と異なる場合があり、この測定は広範な品質・性能の検証を意味しません。

## 機能

Whallm は共通の重みをメモリに置き、選ばれたエキスパートを SSD から読み込みます。DeepSeek V4.1 の Engram 行と Qwen の N-gram 行も、必要なときだけ読み込みます。

| モデル | 高速化 |
| --- | --- |
| DeepSeek V4 | 層ごとの入力処理、エキスパート計算のまとめ実行、FP8 KV キャッシュ、オプションの ANE 投影と DSpark |
| DeepSeek V4.1 | 層ごとの入力処理、エキスパートのまとめ実行、圧縮した KV とインデックスのキャッシュ、候補インデックスだけの採点、CED 入力処理、ANE 投影と DSpark |
| Qwen3.8 | 入力処理中のエキスパートのグループ化、読み込みが終わり次第のエキスパート計算、QSA キャッシュ圧縮、次の層の先読み、MTP |

## Codex の接続

Whallm のサーバーを起動してから、`~/.codex/config.toml` に次を追加します。

```toml
model = "deepseek-v4-flash-0731"
model_provider = "deepseek-v4-ssd"
model_reasoning_effort = "high"

[model_providers.deepseek-v4-ssd]
name = "Whallm"
base_url = "http://127.0.0.1:11434/v1"
wire_api = "responses"
requires_openai_auth = false
```

`model` を API モデル ID、または **Model → Advanced Settings** で設定した Alias に変えて、Codex を再起動します。

- Chat、Status、Throughput に出る名前は表示名で、API モデル ID ではありません。リクエストとベンチマークの JSON は API モデル ID のままです。
- この例は初期設定のアドレスを使い、API キーはありません。Whallm でキーを設定した場合は、クライアントにも同じキーを設定してください。

詳しくは [Codex 設定リファレンス](https://developers.openai.com/codex/config-reference/)を参照してください。

## API とプライバシー

API はテキストのストリーミングとツール呼び出しに対応しています。エンドポイントは次のとおりです。

- `GET /healthz` と `GET /v1/models`
- `POST /v1/responses`
- `POST /v1/chat/completions` と `POST /v1/completions`
- `POST /api/models/load` と `POST /api/models/unload`

**Seed**（v1.1.8 以降）：3 つの生成エンドポイントは、`0`～`4294967295` の `seed` を任意で受け付けます。省略するか `null` を送ると、毎回新しいランダムな seed を使います。Chat では Seed は次のメッセージにだけ使われます。固定した seed で結果を再現できるのは、プロンプト、モデル、設定、実行環境がすべて同じときだけです。バージョン、キャッシュの状態、高速化の設定が違うと、テキストが変わることがあります。`temperature=0` では常に最も確率の高いトークンを選びます。

**ツール**：ツールを実行して結果を返すのはクライアントです。Whallm が MCP ツールを自分で実行することはありません。v1.1.9 以降、すべてのモデルの `/v1/responses` は、`function_call_output.output` として文字列、または `input_text` のリストを受け付けます。各部分は順番どおりに、間に何も足さずにつなげます。リクエスト履歴には、同じ `call_id` の `function_call` を入れてください。

**MiMo（プレビュー）** は、Chat、Responses、アプリの添付ファイルから静止画像と短い PCM WAV 音声を入力できます。

- JSON リクエスト本文：最大 **1 MiB**。
- `/api/assets` へのアップロード（認証が必要）：PNG、JPEG、WebP、PCM WAV と、小さな PDF、DOCX、PPTX、XLSX。1 ファイル最大 **8 MiB**。
- 音声：24 kHz、16-bit PCM WAV、モノラルまたはステレオ。1 クリップ最大 30 秒、1 リクエスト最大 2 クリップ。
- 非対応：音声出力、動画、`logprobs`、`response_format`、`stop`。

詳しくは [MiMo の仕様と制限](docs/mimo-development.md)を参照してください。

**プライバシー**：モデルはあなたの Mac で動きます。Whallm がネットワークを使うのは、ダウンロード、アップデート、API 接続のときだけです。接続したクライアントがデータを外部に送ることはあります。**Debug** ログには、プロンプトやツールの結果がすべて含まれることがあります。

## 検証と制限

- テスト：**Python テスト 705 件が成功**、**Swift テスト 193 件を実行し、4 件スキップ、失敗なし**。
- パッケージの検査では、署名、同梱ファイル、ビルドフォルダーにアクセスできない状態での英語・簡体字中国語・繁体字中国語の起動を確認します。アプリと展開した ZIP の両方が対象です。リリース時は、署名と公証を済ませたダウンロードでもう一度確認します。
- ツール呼び出しのテストは固定のモデル出力を使っており、Pi や Codex の完全なセッションではありません。
- MiMo はプレビューです。固定の事前処理済みファイルを使い、テキスト、画像、短い WAV 音声、一部の文書に対応します。動画、音声と動画の同期、MCP Agent の画面は未完成です。詳しくは[開発状況](docs/mimo-development.md)を参照してください。
- 以前の MTP の測定は、現在の実行環境より前のものです。MTP はすべてのプロンプトで速くなるわけではありません。
- 一部の高速化は、小さなモデルや個別の部品でしかテストしていません。
- とても長いプロンプトでは、より多くのキャッシュメモリが必要です。
