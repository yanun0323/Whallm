Whallm は、必要なエキスパートを SSD から読み込むことで、Apple Silicon Mac 上で大規模言語モデルを動かします。DeepSeek V4、DeepSeek V4.1、Qwen3.8、Swift1.5 Qwen、MiMo（プレビュー）に対応し、チャット画面と OpenAI 互換 API を備えています。

バージョン 1.1.10 では5番目のモデル `Swift1.5-Qwen3.8-Flash-Next` を追加しています。ダウンロード元は `Yanun/Swift1.5-Qwen3.8-Flash-Next-Whallm-MXFP4`、固定リビジョンは `257cb509d72ecc07519be35a8b7558fde3b31b21` です。Qwen FP8 モデルの推論エンジンを再利用しますが、インストール先、保存設定、Alias、プロンプトキャッシュは独立しています。API model ID は `swift1.5-qwen3.8-flash-next-mxfp4` です。アプリに固定値として表示するダウンロード容量は **127,714,522,478 bytes**（約 **118.94 GiB**）です。従来のテキスト／MTP用59ファイルに **897,864,704 bytes** の画像用重みを加えた値で、監査ファイルは含みません。2 つの Qwen モデルの詳細設定は同じで、Alias、生成、メモリ、読み込みワーカー、プロンプトキャッシュ、ウォームアップ、MTP のみを表示し、その他の実行オプションは MTP の戦略、ソート済みエキスパート Prefill、マスク QSA Prefill を含めて固定値を使います。MTP は既定でオンで、出力は MTP なしの場合とわずかに異なることがあります。

両方の Qwen モデルで、App Chat、`/v1/chat/completions`、`/v1/responses` から静止 PNG／JPEG／WebP 画像を入力できます。新規インストールには画像用重みが含まれます。既存のインストールでは **Model → Verify and Repair** で不足・破損ファイルのみを取得し、正常なテキスト用重みは再ダウンロードしません。元の Qwen の容量は **126,189,355,659 bytes**（約 **117.52 GiB**）です。画像入力には MTP をオフにする必要があり、プロンプトキャッシュは使いません。上限は1リクエスト8枚、1ファイル8 MiB、合計32 MiB、各画像のデコード／リサイズ後1,048,576画素、合計2,048画像トークンです。Qwen の動画・音声・文書入力は非対応です。Swift のフルモデルで赤／青の画像認識と、画像リクエストおよび中断の前後で短いテキスト結果が一致することを確認しました。元の Qwen のフルモデルでの画像入力への応答、幅広い画像品質、画像処理性能は未検証です。

## はじめに

1. [GitHub Releases](https://github.com/yanun0323/Whallm/releases) から `Whallm-macOS-arm64.zip` をダウンロードし、展開して `Whallm.app` を開きます。
2. **Model** でモデルを選び、**Download Model** を押します。アプリが空き容量を確認し、中断したダウンロードは再開できます。
3. **Server** で **Start Server** を押します。
4. **Chat** でモデルを選ぶか、下の設定例で API クライアントを接続します。

既定のアドレスは `http://127.0.0.1:11434` です。モデルは最初の利用時に読み込まれます。サーバーは一度に 1 つのモデルを保持し、生成リクエストを順番に処理します。新しくインストールしたモデルがチャットの選択肢に表示されない場合は、サーバーを再起動してください。

変更点、更新手順、既知の制限は [1.1.10 の英語リリースノート](Packaging/ReleaseNotes/1.1.10.md)を参照してください。

## 動作環境

| 項目 | 要件 |
| --- | --- |
| Mac | Apple Silicon、macOS 15 以降 |
| ユニファイドメモリ | 64 GiB 推奨。使用量はモデルと設定によって変わります |
| ストレージ | 高速な内蔵 SSD、Thunderbolt SSD、または USB4 SSD |
| 空き容量 | ダウンロード済みの部分も考慮して、アプリがモデルごとの必要容量を計算します |
| ネットワーク | モデルのダウンロードとアプリの更新に必要です |

モデルの重みはアプリに含まれません。DeepSeek V4.1 はエキスパートと Engram のファイルだけで約 **458 GiB** を使い、さらに共通の重みとメタデータが必要です。

## 機能

Whallm は共通の重みをメモリに保持し、選択されたエキスパートを SSD から読み込みます。DeepSeek V4.1 の Engram と Qwen の N-gram も、必要な行だけを読み込みます。

| モデル | 高速化の選択肢 |
| --- | --- |
| DeepSeek V4 | レイヤー単位の入力処理、エキスパートの一括計算、FP8 KV キャッシュ、任意の ANE 射影と DSpark |
| DeepSeek V4.1 | レイヤー単位の入力処理、エキスパートの一括計算、圧縮した KV・インデックスキャッシュ、候補だけのインデックス評価、CED 入力処理、ANE 射影、DSpark |
| Qwen3.8 | 入力処理時のエキスパートの一括計算、読み込みが終わったエキスパートからの計算、QSA キャッシュ圧縮、次レイヤーの先読み、ANE 射影、MTP |

自分の Mac で測定するには、**Throughput** を開き、インストール済みのモデル、**Code** または **Novel**、**1K～200K** の入力長、**128・512・1024・4096** の出力上限を選びます。結果はプレーンテキスト、JSON、Markdown でコピーできます。測定の完了時またはキャンセル時に、アプリは測定用モデルをメモリから解放します。ローカルビルドでは、模擬結果を出す **Dry run** も使えます。

SSD の速度、プロンプトの長さ、キャッシュ状態、設定によって結果は変わります。

## Codex の接続

Whallm のサーバーを起動し、ユーザー設定の `~/.codex/config.toml` に以下を追加します。

```toml
model = "deepseek-v4-flash-0731"
model_provider = "deepseek-v4-ssd"
model_reasoning_effort = "high"

[model_providers.deepseek-v4-ssd]
name = "Whallm"
base_url = "http://127.0.0.1:11434/v1"
wire_api = "responses"
requires_openai_auth = false
```

`model` を API モデル ID、または **Model → Advanced Settings** で設定した Alias に変更し、Codex を再起動します。Chat、Status、Throughput、テキスト／Markdown の結果表では Model ページと同じ表示名を使います。表示名は API モデル ID ではありません。API リクエストとベンチマーク JSON の識別子は変更しません。この例は既定のローカルアドレスを使い、API キーを設定しない場合のものです。Whallm にキーを設定した場合は、クライアントにも同じキーを設定してください。[Codex の設定リファレンス](https://developers.openai.com/codex/config-reference/)も参照できます。

## API とプライバシー

API はテキストのストリーミングとツール呼び出しに対応し、以下のエンドポイントを提供します。

- `GET /healthz` と `GET /v1/models`
- `POST /v1/responses`
- `POST /v1/chat/completions` と `POST /v1/completions`
- `POST /api/models/load` と `POST /api/models/unload`

3つの生成エンドポイントで `0`〜`4294967295` の整数を任意の `seed` として指定できます。省略または `null` の場合、リクエストごとに新しい乱数シードを使います。Playground Chat の Seed は次のメッセージだけに適用され、送信後に空になります。固定シードは同じ入力、モデル、設定、実行環境での再現に役立ちますが、バージョン、キャッシュ状態、高速化設定が異なる場合の完全一致は保証しません。`temperature=0` は引き続き最大確率の候補を選びます。v1.1.8 から利用できます。

ツールはクライアント側で実行し、結果を返します。推論 API が MCP ツールを自動実行することはありません。MiMo（プレビュー）の静止画像と制限付き PCM WAV 音声入力を Chat／Responses とアプリの添付機能から利用できます。JSON 本文は引き続き **1 MiB** までで、認証付き `/api/assets` は PNG／JPEG／WebP、PCM WAV と、対応範囲を限定した PDF／DOCX／PPTX／XLSX 文書を1ファイル **8 MiB** まで受け付けます。音声入力は 24 kHz・16ビット PCM WAV、モノラル／ステレオ、1本30秒以内、1リクエスト2本までです。音声出力、動画、`logprobs`、`response_format`、`stop` は未対応です。[MiMo の仕様と制限](docs/mimo-development.md)を参照してください。

すべてのモデルで `/v1/responses` の `function_call_output.output` に文字列または `input_text` の配列を指定できます。テキストは順番に連結され、既存の空白と改行は保持されます。区切り文字は追加しません。リクエストの履歴には、同じ `call_id` を持つ `function_call` を含めてください。メディアの対応範囲は引き続きモデルによって異なります。v1.1.9 から利用できます。

推論は Mac 上で実行されます。ダウンロード、更新、API 接続にはネットワークを使います。接続先のクライアントがデータを外部に送信する場合があります。**Debug** ログにはプロンプトやツールの結果が全文で含まれることがあります。

## 検証と制限

ソースの検証では **Python テスト 674 件が合格**し、**Swift テスト 196 件を実行、4 件スキップ、失敗なし**でした。パッケージ検証はアプリと ZIP 展開版の署名、同梱リソース、ビルドディレクトリにアクセスできない環境での英語・簡体字中国語・繁体字中国語による起動を確認します。リリース時には正式に署名・公証したパッケージと GitHub ダウンロード版でも再確認します。ツール呼び出しの回帰テストは固定のモデル出力を使っており、Pi や Codex クライアントでの一連の対話を検証したものではありません。

MiMo は引き続きプレビューで、固定リビジョンの変換済み artifact を使い、テキスト／画像、制限付き WAV 音声、限定的な文書入力に対応します。全体の受け入れ検証は未完了です。チャット添付には種類別ファイル選択、ドラッグ＆ドロップ、容量表示、アップロード状況があります。動画／音声映像同期と MCP Agent 画面は未完成で、音声・文書入力には形式とリソースの制限があります。[開発状況](docs/mimo-development.md)を参照してください。Qwen の画像検証範囲は上記のとおりです。過去の MTP 測定は最終修正版の測定ではなく、MTP がすべての処理で速くなるとは限りません。一部の高速化処理は小規模モデルと部品単位でのみ検証しています。長いプロンプトには、より多くのキャッシュメモリが必要です。
