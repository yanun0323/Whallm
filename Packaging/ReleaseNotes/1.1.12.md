# Whallm 1.1.12

Changes since v1.1.11.

## Use less memory with 8-bit resident weights

- Both Qwen models have a new setting, **Use 8-bit resident weights**, in **Model → Advanced Settings**. It is off by default.
- When it is on, the weights that stay in memory, except experts, are kept in 8 bits instead of BF16. This uses less memory and usually speeds up output, most with MTP on.
- Output can differ slightly from output with the setting off.
- **Estimated peak memory** now drops when you turn the setting on. For Swift1.5 the estimate is about 3.7 GiB lower.

## New Qwen defaults

- **Experts in memory** now defaults to 8.5% (2,089 slots, about 5.1 GiB). It was about 12.5% (7.5 GiB).
- **MTP experts in memory** now defaults to 100% (512 slots, about 1.2 GiB). It was about 8%.
- Together, the two defaults use about 1.3 GiB less memory than before.

## Less work per token for Qwen

- Output no longer rebuilds each expert's weight views for every token. They are built once and reused.
- When the main model checks MTP drafts, it no longer copies the whole attention history every round.
- N-gram lookups ask macOS for all the pages they need at once instead of one at a time.
- Loading reads large weights with four workers.
- QSA index keys are stored once instead of twice.

Output tokens are unchanged by these five changes.

## DeepSeek V4.1

- Engram lookups ask macOS for all the pages they need at once, as Qwen N-gram lookups do.

## Upgrade notes

- The new defaults apply to new installs and when you reset a model's settings. Your saved settings are kept.
- Prompt Cache entries saved with **Use 8-bit resident weights** on are kept apart from entries saved with it off.

## Benchmarks

Measured with the built-in **Throughput** test on a build from source shortly before this release: Swift1.5, MTP and **Use 8-bit resident weights** on, **Code** input, a 512-token output limit, 2,089 expert slots, temperature 0 and seed 42.

| Chip | Input tokens | TTFT (ms) | Prefill (tok/s) | Decode (tok/s) | Peak MLX (GiB) |
| --- | ---: | ---: | ---: | ---: | ---: |
| M5 Pro | 4096 | 6976.5 | 587.1 | 19.4 | 13.13 |
| M5 Pro | 8192 | 13911.4 | 588.9 | 19.8 | 13.86 |
| M5 Pro | 16384 | 29654.2 | 552.5 | 18.6 | 14.29 |
| M2 Max | 4096 | 15151.2 | 270.3 | 15.0 | 13.15 |
| M2 Max | 8192 | 30693.5 | 266.9 | 15.8 | 13.84 |
| M2 Max | 16384 | 65538.0 | 250.0 | 14.7 | 14.42 |

The v1.1.11 run on the same M5 Pro peaked at 16.93 to 18.81 GiB and produced 14.6 to 17.5 tokens per second. That run used a 128-token output limit and did not have 8-bit resident weights, so this is not a controlled comparison.

## Validation

- **719 Python tests passed**; **195 Swift tests ran, with 4 skipped and no failures**.
- Packaging checks cover signatures, bundled files and startup in English, Simplified Chinese and Traditional Chinese without access to the build folder, for both the App and the unzipped download.

## Known limits

- **Estimated peak memory** was about 2 GiB higher than the measured peak in the runs above. The estimate includes a safety allowance and memory that MLX holds for reuse; the measured number does not.
- The lower estimate for 8-bit resident weights is calculated from the model's file list. It was compared with measurements only for Swift1.5.
- There are no measurements for Qwen3.8 FP8 with 8-bit resident weights.
- The benchmark rows come from one M5 Pro and one M2 Max.

Requires Apple Silicon and macOS 15 or later. Model weights are downloaded separately. This is a distribution build; local-only debug and Dry run features are not included.
