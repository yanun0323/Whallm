# Whallm 1.1.10

Changes since v1.1.9.

## New model: Swift1.5 Qwen

- Add `Swift1.5-Qwen3.8-Flash-Next`, including download, verification, repair, Chat, and API support.
- Download a pinned, prepared MXFP4 artifact without converting the original FP8 checkpoint. The API model ID is `swift1.5-qwen3.8-flash-next-mxfp4`.
- Reuse the existing Qwen inference engine while keeping installation folders, settings, Aliases, and prompt caches separate from the original Qwen model. The new model includes its own MTP weights; MTP remains off by default.

## Still images for both Qwen models

- Accept PNG, JPEG, and WebP images in App Chat, `/v1/chat/completions`, and `/v1/responses` for both Qwen3.8-Flash-Next and Swift1.5 Qwen.
- Include pinned image weights in new installations. Existing installations can fetch only missing or damaged files through **Model → Verify and Repair**, without redownloading intact text weights.
- Keep image processing separate from text prompt caches and load image weights only for image requests. Check missing or damaged image files and incompatible MTP settings before starting the response stream.

**Upgrade note:** Run **Verify and Repair** for an existing Qwen installation to add its approximately 0.90 GB image-weight file. Turn off MTP and reload the model before sending images. Image requests bypass prompt caching. The total installed payload is about 117.52 GiB for the original Qwen model and 118.94 GiB for Swift1.5 Qwen.

Image limits are 8 images per request, 8 MiB per file, 32 MiB combined, 1,048,576 pixels per decoded/resized image, and 2,048 image tokens per request. Qwen video, audio, and document input are not supported.

## Qwen MTP improvements

- Fill the draft layer's attention cache from the whole prompt after layer-major input processing, rather than only a short tail. Read the draft layer's experts once for this step.
- Allow Prefill acceleration to remain enabled with MTP for text requests.
- Restore state after rejected drafts without replaying accepted tokens through routed experts. Retain unaffected pooled attention blocks.
- Wait for recurrent, convolution, and N-gram state calculations before recording rewind time, avoiding understated timing results.

## Tool calls and model names

- Fix Qwen streamed tool calls being rejected when whitespace between consecutive calls arrives in a later chunk. This could stop clients such as Pi with `The streamed tool call failed validation.` Invalid or incomplete calls are still rejected.
- Keep the Responses API's complete-output validation and event format unchanged. Add regression coverage for multiple Codex-style tool calls, tool results, and the following answer.
- Use consistent model display names in Model, Chat, Status, Throughput, and text/Markdown result tables. New Chat records retain the stable model ID so changing an Alias does not change their model identity. Existing API IDs, Alias routing, and benchmark JSON identifiers are unchanged.

## Packaging and validation

- Bundle and verify both Qwen image definitions alongside the model catalog. Extend packaged startup checks to verify that image resources are available without the source checkout or Swift build resources.
- Update all five README languages and clarify the limits of historical performance measurements.
- Source regression coverage: **674 Python tests passed**; **196 Swift tests ran, with 4 skipped and no failures**. An additional **126 packaged Python tests** passed with access to the project and Homebrew denied.

## Known limits

- Swift-model image checks cover short red/blue recognition, image-token limits, cancellation, and text consistency. They do not establish broad image quality or performance. Full original-Qwen image generation remains unvalidated.
- Tool-call API tests use fixed model output, not a complete Pi or Codex client session.
- MTP performance depends on the workload. Historical measurements predate the final timing correction and are not measurements of this release. MTP and non-MTP output can differ; no universal speedup or output-equivalence guarantee is claimed.
- MiMo remains a preview. This release does not include the separate Qwen Native engine from the development branch.

Requires Apple Silicon and macOS 15 or later. Model weights are downloaded separately. This is a distribution build; local-only debug and Dry run features are not included.
