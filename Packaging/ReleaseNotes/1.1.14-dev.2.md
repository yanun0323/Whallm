# Whallm 1.1.14-dev.2

Development prerelease. Changes since v1.1.14-dev.1. Select **Settings → Updates → Dev** to receive dev updates; the stable channel remains on v1.1.13.

## Qwen thinking limits

- Both Qwen3.8-Flash-Next and Swift1.5-Qwen3.8-Flash-Next now support an optional thinking limit. At the limit, the engine closes the thinking block and continues answering or making tool calls within the same request.
- In **Model → Advanced Settings**, **Max tokens** is now **Total output limit**. Enable **Limit thinking** to set **Thinking limit**. Thinking, its closing marker, answers and tool calls all count toward the total output limit.
- Chat, Responses and Completions APIs accept `think_budget`. Omit it to use the App/catalog default, use `null` to disable it for one request, or use `0` to end an open thinking block immediately. Other models reject a non-null budget.
- Leave at least two output tokens beyond the thinking budget, and substantially more for useful answers. For example, `think_budget: 8192` with `max_tokens: 16384` leaves up to 8,191 answer tokens after the closing marker. API output limits override the App default.
- MTP remains available and verification stops at the thinking boundary. The closing marker is included in token usage and prompt-cache history. Requests with insufficient context space are rejected rather than silently consuming the reserved answer space.
- The budget is off by default. Existing settings and total output limits are preserved. Built-in throughput tests ignore the thinking budget.

## Qwen MTP scheduling

- The shared Qwen Native engine overlaps shared-expert computation with routing and required expert reads during 2–6-row MTP verification. No new setting is needed; single-token decoding, prefill and the draft layer keep their existing schedules.
- The change preserves the arithmetic and does not prefetch guessed experts. A prior short Swift-only M2 Max experiment observed about 2.15% faster decoding overall. This is limited evidence, not a general speed guarantee; other models, Macs and long contexts have not been validated for this release.

## Upgrade and validation limits

- Quit the old App and restart with this build. No model redownload or settings reset is required. Enable the thinking limit explicitly if wanted, and ensure client-supplied output limits leave enough room for an answer.
- Fixed-output tests cover the 8,192-token boundary, MTP on/off, cancellation, cache continuation, image-prefill handling, API streaming and tool calls. They do not establish real-model answer or tool quality.
- Prior short real Swift-model checks cover forced thinking transitions with MTP on/off, repeat generation and state-file round trips. M2 Max checks also compare verification logits and state against the preceding schedule. These are not broad quality validation, full Qwen FP8 or real-image validation, or an 8,192-token remote Mho session test.
- Forcing thinking to end does not guarantee a correct or complete answer. This remains a dev build; MiMo remains a preview, and the server handles one generation request at a time.
- See [the usage reference](https://github.com/yanun0323/Whallm/blob/v1.1.14-dev.2/docs/usage.md) for the API contract and examples.
