Whallm은 Apple Silicon Mac에서 대규모 언어 모델을 실행하는 앱입니다. 이런 모델은 '전문가'라고 부르는 작은 부분 여러 개로 이루어져 있고, 단어 하나에는 그중 몇 개만 쓰입니다. Whallm은 모든 단어에 쓰이는 부분을 메모리에 두고, 전문가는 필요할 때만 SSD에서 읽습니다. 그래서 Mac 메모리보다 훨씬 큰 모델도 실행할 수 있습니다. 채팅 창과 OpenAI 호환 API를 함께 제공합니다.

지원 모델: DeepSeek V4, DeepSeek V4.1, Qwen3.8, Swift1.5 Qwen3.8, MiMo(미리 보기).

## 벤치마크 요약

사용자가 v1.1.13에서 **Swift1.5-Qwen3.8-Flash-Next**를 16K 토큰 입력, 512 토큰 답변으로 측정했습니다. **Prefill**은 Whallm이 입력을 읽는 속도이고, **Decode**는 답변을 쓰는 속도입니다. 둘 다 초당 토큰 수입니다.

| 칩 | 캐시 모드 | Slots | Prefill (tok/s) | Decode (tok/s) | 최대 메모리 (GiB) |
| --- | --- | --- | --- | --- | --- |
| M2 Max | 자동 | 8192 | 286.4 | 19.4 | 31.71 |
| M2 Max | 고정 | 2089 | 289.6 | 16.5 | 16.99 |
| M5 Pro | 자동 | 8192 | 521.1 | 25.6 | 31.11 |
| M5 Pro | 고정 | 2089 | 536.0 | 21.7 | 16.25 |

자동 모드에서는 Whallm이 캐시 크기를 정합니다. 고정 모드는 더 작은 정해진 크기를 써서 메모리를 덜 쓰지만, 답변을 쓰는 속도는 느립니다.

> 자세한 내용은 [전체 벤치마크](#벤치마크)를 참고하세요.

## 시작하기

1. [GitHub Releases](https://github.com/yanun0323/Whallm/releases)에서 `Whallm-macOS-arm64.zip`을 내려받아 압축을 풀고 `Whallm.app`을 엽니다.
2. **Model**을 열고 모델을 고른 뒤 **Download Model**을 선택합니다. 앱이 먼저 남은 공간을 확인합니다. 내려받기가 멈춰도 이어서 받을 수 있습니다.
3. **Server**를 열고 **Start Server**를 선택합니다.
4. **Chat**을 열어 모델을 고르거나, 아래 예시처럼 API 클라이언트를 연결합니다.

서버의 기본 주소는 `http://127.0.0.1:11434`입니다. 모델은 처음 사용할 때 불러옵니다. 서버는 한 번에 모델 하나만 불러오고, 요청도 하나씩 처리합니다. 방금 설치한 모델이 Chat 목록에 없으면 서버를 다시 시작하세요.

[1.1.13 릴리스 노트](Packaging/ReleaseNotes/1.1.13.md)에 변경 사항, 업그레이드 방법, 알려진 제한이 있습니다.

## 실행 환경

| 항목 | 조건 |
| --- | --- |
| Mac | Apple Silicon, macOS 15 이상 |
| 메모리 | 64 GiB 권장. 실제 사용량은 모델과 설정에 따라 다릅니다 |
| 저장 장치 | 빠른 내장, Thunderbolt 또는 USB4 SSD |
| 남은 공간 | 받다 만 파일을 포함해 모델마다 필요한 공간을 앱이 보여 줍니다 |
| 네트워크 | 모델과 앱 업데이트를 내려받을 때 필요합니다 |

앱에는 모델 가중치가 들어 있지 않습니다. DeepSeek V4.1만 해도 전문가와 Engram 파일에 약 **458 GiB**가 필요하고, 다른 가중치도 따로 필요합니다.

## Qwen 모델

두 Qwen 모델은 MLX 대신, Whallm이 C++와 Metal로 직접 만든 엔진(**Native 엔진**)을 사용합니다. 내려받은 파일, 모델 이름, API ID, Alias는 그대로입니다. 클라이언트가 아직 예전 `-Native` 테스트 ID를 쓰고 있다면 아래 ID로 바꾸세요. 예전 MLX 엔진이 저장한 프롬프트 캐시는 이어서 쓰지 않습니다.

### Swift1.5-Qwen3.8-Flash-Next

1.1.10에서 추가되었습니다.

- API model ID: `swift1.5-qwen3.8-flash-next-mxfp4`
- 출처: `Yanun/Swift1.5-Qwen3.8-Flash-Next-Whallm-MXFP4`, revision `257cb509d72ecc07519be35a8b7558fde3b31b21`
- 내려받기 크기: **127,714,522,478 bytes**(약 **118.94 GiB**). 이미지 가중치 **897,864,704 bytes**가 포함됩니다.
- Qwen3.8 FP8과 같은 엔진을 쓰지만, 폴더, 설정, Alias, 프롬프트 캐시는 따로 있습니다.

### Qwen3.8-Flash-Next

- API model ID: `qwen3.8-flash-next-fp8`
- Swift1.5와 같은 엔진과 설정을 쓰고, 설치, Alias, 프롬프트 캐시는 따로 있습니다.

### 설정

- **Advanced Settings**에는 생성, 전문가 캐시 크기, 읽기 작업자, Prompt Cache, 워밍업, MTP, 8-bit 상주 가중치가 있습니다.
- **Size the expert cache automatically**는 기본으로 켜져 있습니다. 켜져 있으면 Whallm은 모델을 불러올 때 남아 있는 메모리를 최대 약 20 GiB까지 쓰고, macOS와 다른 앱을 위해 적어도 7 GiB 또는 이 Mac 메모리의 15%를 남겨 둡니다. 끄면 정해진 크기를 직접 고를 수 있습니다.
- **MTP**는 다음 몇 단어를 미리 추측한 뒤, 맞는지 확인합니다. 기본으로 켜져 있고 대개 답변이 빨라지지만, 모든 프롬프트에서 빨라지지는 않습니다. MTP를 껐을 때와 문장이 조금 다를 수 있습니다.
- **Use 8-bit resident weights**는 메모리에 계속 두는 부분을 더 작은 형식으로 저장합니다. 메모리를 덜 쓰고 대개 답변도 빨라지며, MTP를 켰을 때 효과가 가장 큽니다. 이 설정을 껐을 때와 문장이 조금 다를 수 있습니다. 새 설정이나 기본값으로 되돌린 설정에서는 켜져 있고, 저장된 설정은 기존 선택을 유지합니다.

### 이미지

- 두 Qwen 모델은 Chat, `/v1/chat/completions`, `/v1/responses`에서 정지 PNG, JPEG, WebP 이미지를 받습니다.
- 이미지는 MTP를 켜든 끄든 쓸 수 있습니다. 이미지가 있는 요청은 프롬프트 캐시를 쓰지 않습니다.
- 요청 한 번에 이미지 8장, 파일당 8 MiB, 합계 32 MiB까지 보낼 수 있습니다. 각 이미지는 최대 1,048,576픽셀로 줄어들고, 모든 이미지를 합쳐 이미지 토큰을 최대 2,048개까지 씁니다.
- 새로 설치하면 이미지 가중치가 포함됩니다. 예전 설치에서는 **Model → Verify and Repair**를 선택하세요. 없거나 손상된 파일만 내려받습니다. Qwen3.8 FP8 전체 설치는 **126,189,355,659 bytes**(약 **117.52 GiB**)입니다.
- Qwen은 동영상, 오디오, 문서를 받지 않습니다.
- M2 Max에서 두 모델 모두 짧은 텍스트, Chat, Responses, 스트리밍, 이미지가 정상적으로 작동했습니다. 예전 MLX 엔진과는 문장이 다를 수 있습니다. 이 확인만으로 모든 용도의 품질이나 속도가 보장되지는 않습니다.

## DeepSeek V4.1

DeepSeek V4.1도 MLX 대신 자체 Native 엔진으로 실행됩니다. 내려받은 파일, 모델 이름, API ID, Alias는 그대로입니다. 예전 MLX 엔진이 저장한 프롬프트 캐시는 이어서 쓰지 않습니다.

- **Advanced Settings**에는 생성, 전문가 캐시 크기, 읽기 작업자, Prompt Cache, 워밍업, DSpark가 있습니다.
- **Size the expert cache automatically**는 기본으로 켜져 있습니다. 켜져 있으면 Whallm은 모델을 불러올 때 남아 있는 메모리를 최대 약 72 GiB까지 쓰고, macOS와 다른 앱을 위해 적어도 7 GiB 또는 이 Mac 메모리의 15%를 남겨 둡니다. 정해진 크기를 직접 고를 때는 전문가를 적어도 96개 담을 수 있어야 합니다.
- MLX에서만 쓰던 설정은 없어졌습니다. 예를 들어 근사 모드, ANE projection, MLX 메모리 기준입니다. 근사 모드를 요구하는 요청은 거부됩니다.
- **DSpark**는 다음 여러 단어를 미리 추측한 뒤, 맞는지 확인합니다. DSpark의 전문가는 기본 전문가 캐시를 함께 쓰기 때문에, 따로 정하는 캐시 크기는 없어졌습니다. greedy 샘플링에서는 DSpark가 문장을 바꾸지 않습니다. 코드처럼 예측하기 쉬운 글에서 가장 효과가 크고, 다른 글에서는 껐을 때보다 조금 느릴 수 있습니다.
- M5 이후 칩에서는 긴 입력에 GPU의 Neural Accelerators를 씁니다. M5에서는 아직 측정하지 않았습니다.
- M2 Max(64 GiB)에서 파일 캐시를 먼저 비운 뒤 측정했습니다. 3,000토큰 Code 프롬프트는 약 70 tok/s, 16,000토큰은 약 140 tok/s로 읽었습니다. DSpark 없이 답변은 약 3.4 tok/s로 썼습니다. 최근 속도 개선 뒤로 DSpark 속도는 아직 다시 측정하지 않았습니다. greedy 샘플링에서는 출력이 예전 MLX 엔진과 같았습니다. 품질, 16,000토큰보다 긴 입력, M5는 아직 테스트하지 않았습니다.

## 기능

Whallm은 모든 단어에 쓰이는 부분을 메모리에 두고, 필요한 전문가만 SSD에서 읽습니다. DeepSeek V4.1의 Engram 행과 Qwen의 N-gram 행도 필요할 때만 읽습니다.

| 모델 | 빠르게 하는 방법 |
| --- | --- |
| DeepSeek V4 | 입력을 한 층씩 읽고, 전문가 계산을 묶어서 하고, 더 작은(FP8) 어텐션 캐시를 쓰며, ANE projection과 DSpark를 제공합니다 |
| DeepSeek V4.1 | Native 엔진: 긴 입력에서는 전문가마다 한 번만 읽고, GPU가 계산하는 동안 읽습니다. 답변을 쓸 때는 메모리에 있는 전문가부터 계산합니다. DSpark는 추측을 확인할 때 남긴 단어를 다시 계산하지 않습니다 |
| Qwen3.8 | 입력을 읽을 때 전문가를 묶어서 계산하고, 읽기가 끝나는 대로 바로 계산하고, QSA 캐시를 압축하고, 다음 층을 미리 읽고, MTP를 씁니다 |

## 벤치마크

### v1.1.13: Swift1.5 · Native 엔진

아래 모든 행은 512토큰 답변을 요청했고, 실제로 512토큰을 출력했습니다. 자동 모드는 이 Mac들에서 8,192 slots를 골랐고, 고정 모드는 2,089를 썼습니다. 다른 Mac이나 남은 메모리가 적을 때는 자동 모드가 다른 크기를 고를 수 있습니다. 측정한 사람이 프롬프트 종류, 설정, 캐시 상태, 전체 환경을 기록하지 않았으므로, 참고용으로만 보고 예전 버전과 공정하게 비교하는 데는 쓰지 마세요.

- **TTFT**: 첫 토큰이 나올 때까지 걸린 시간. **TPOT**: 출력 토큰 하나에 걸린 시간.
- **Prefill**과 **Decode**: 초당 입력 토큰 수와 출력 토큰 수.
- **Total**: 시작부터 끝까지 걸린 시간. **Throughput**: 초당 입력과 출력을 합한 토큰 수.
- **최대 메모리**: 보고된 프로세스 메모리 사용량의 최댓값이며, Mac 전체 사용량이 아닙니다. 앱은 약 10 ms마다 메모리를 확인하므로, 아주 짧은 최고점은 기록되지 않을 수 있습니다. 출처에는 앱 자체가 포함되었는지 나와 있지 않습니다.

## Codex 연결

Whallm 서버를 시작한 뒤, 다음 내용을 `~/.codex/config.toml`에 추가하세요.

```toml
model = "deepseek-v4-flash-0731"
model_provider = "deepseek-v4-ssd"
model_reasoning_effort = "high"

[model_providers.deepseek-v4-ssd]
name = "Whallm"
base_url = "http://127.0.0.1:11434/v1"
wire_api = "responses"
requires_openai_auth = false
```

`model`에는 API model ID나 **Model → Advanced Settings**에서 정한 Alias를 넣으세요. 그런 다음 Codex를 다시 시작하세요.

- Chat, Status, Throughput에 보이는 이름은 표시 이름이며 API model ID가 아닙니다. 요청과 벤치마크 JSON에는 계속 API model ID를 씁니다.
- 이 예시는 기본 주소를 쓰고 API key는 쓰지 않습니다. Whallm에서 key를 정했다면 클라이언트에도 같은 key를 넣으세요.

[Codex 설정 참고 문서](https://developers.openai.com/codex/config-reference/)도 확인하세요.

## API와 개인정보

API는 텍스트 스트리밍과 도구 호출을 지원합니다. 엔드포인트는 다음과 같습니다.

- `GET /healthz`와 `GET /v1/models`
- `POST /v1/responses`
- `POST /v1/chat/completions`와 `POST /v1/completions`
- `POST /api/models/load`와 `POST /api/models/unload`

**Seed**(v1.1.8부터): 세 생성 엔드포인트 모두 `0`부터 `4294967295`까지의 `seed`를 선택적으로 받습니다. 빼거나 `null`을 보내면 매번 새로운 무작위 seed를 씁니다. Chat에서 Seed는 다음 메시지에만 적용됩니다. 같은 seed로 같은 결과가 나오려면 프롬프트, 모델, 설정, 버전이 모두 같아야 합니다. 캐시 상태나 속도 개선 설정이 다르면 문장이 바뀔 수 있습니다. `temperature=0`에서는 항상 확률이 가장 높은 토큰을 고릅니다.

**도구**: 도구를 실행하고 결과를 보내는 것은 클라이언트입니다. Whallm은 MCP 도구를 직접 실행하지 않습니다. v1.1.9부터 모든 모델의 `/v1/responses`는 `function_call_output.output`으로 문자열이나 `input_text` 목록을 받습니다. 각 부분은 사이에 아무것도 넣지 않고 순서대로 이어 붙입니다. 요청 기록에는 같은 `call_id`를 가진 `function_call`을 포함하세요.

**MiMo(미리 보기)**는 Chat, Responses, 앱 첨부 파일로 정지 이미지와 짧은 PCM WAV 오디오를 받습니다.

- JSON 요청 본문: 최대 **1 MiB**.
- `/api/assets` 업로드(로그인 필요): PNG, JPEG, WebP, PCM WAV와 작은 PDF, DOCX, PPTX, XLSX 파일. 파일당 최대 **8 MiB**.
- 오디오: 24 kHz, 16-bit PCM WAV, 모노 또는 스테레오. 한 개당 최대 30초, 요청당 최대 두 개.
- 지원하지 않음: 오디오 출력, 동영상, `logprobs`, `response_format`, `stop`.

[MiMo 규격과 제한](docs/mimo-development.md)을 참고하세요.

**개인정보**: 모델은 내 Mac에서 실행됩니다. Whallm은 내려받기, 업데이트, API 연결에만 네트워크를 씁니다. 연결한 클라이언트가 데이터를 다른 곳으로 보낼 수는 있습니다. **Debug**는 설정과 캐시 정보를 기록하지만, 프롬프트 전문, 도구 결과, 이미지, API key는 기록하지 않습니다. 로그를 `~/.whallm/server.log`에 저장할 수도 있습니다(최대 10 MB, 가장 오래된 내용부터 지웁니다). 로그에는 로컬 경로와 네트워크 주소가 들어 있을 수 있으니, 공유하기 전에 확인하세요.

## 검증과 제한

- 테스트: **Python 테스트 786개 통과, 4개 건너뜀**, **Swift 테스트 209개 통과, 4개 건너뜀**. 실패는 없습니다.
- 패키지를 만들 때 앱의 서명과 포함된 파일을 확인하고, 빌드 폴더에 접근할 수 없는 상태에서도 영어, 중국어 간체, 중국어 번체로 시작되는지 확인합니다. 앱과 압축을 푼 ZIP 모두 확인합니다. 정식 릴리스에서는 서명과 공증을 마친 다운로드에서 한 번 더 확인합니다.
- 도구 호출 테스트는 정해진 모델 출력을 씁니다. Pi나 Codex의 전체 세션이 아닙니다.
- MiMo는 미리 보기입니다. 미리 준비해 둔 고정된 모델을 쓰며, 텍스트, 이미지, 짧은 WAV 오디오, 일부 문서를 지원합니다. 동영상, 오디오와 영상 동기화, MCP Agent 화면은 아직 완성되지 않았습니다. [개발 현황](docs/mimo-development.md)을 참고하세요.
- 예전 MTP 측정은 지금 엔진보다 먼저 이루어졌습니다. MTP가 모든 프롬프트에서 빨라지지는 않습니다.
- 일부 속도 개선은 작은 모델이나 단일 부분에서만 테스트했습니다.
- 아주 긴 프롬프트에는 더 많은 캐시 메모리가 필요합니다.
